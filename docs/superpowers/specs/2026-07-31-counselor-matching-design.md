## 과제 배경

과제 요구사항 원문: "지금까지 만들었던 웹사이트와 기획 내용(상담사 매칭 및 리스트, 회원가입 로그인 등 기능)을 넣어 실제 동작하는 웹 어플리케이션을 만들어보세요."

배포 방식은 과제에 명시됨:
1. 프론트엔드 → Vercel
2. 백엔드 → Railway (또는 사용 중인 다른 서비스)
3. DB → 외부 DB, MongoDB Atlas Free Tier 추천 (또는 사용 중인 다른 서비스)

## 대상 사용자 (중요 컨텍스트)

- **상담사**: 상담/심리 전공 대학생 (20대). 자격증 인증 같은 무거운 절차는 불필요 — 전공/학년/관심분야 위주 프로필로 충분.
- **내담자**: 10대~20대 (미성년자 포함될 수 있음, 이번 과제 범위에서는 별도 보호자 동의 절차는 고려하지 않기로 함 — 필요 시 추후 논의).

## 지금까지 확정된 결정 사항

| 항목 | 결정 | 비고 |
|---|---|---|
| 회원가입 구조 | 가입 시 역할 선택 (상담사/내담자 선택 후 각각 다른 화면) | 별도 URL 분리 방식은 채택 안 함 |
| 매칭 방식 | 리스트 탐색 + 내담자가 직접 상담사 선택/신청 | 필터/검색이나 설문 기반 자동매칭은 이번 범위 아님 |
| 신청-수락 플로우 | 내담자가 신청 → 상담사가 대시보드에서 **수락/거절** (거절 시 **사유 선택** 가능) → 수락 시 매칭 확정 | pending/accepted/rejected 상태 관리 필요 |
| 데이터 저장 | 실제 DB 사용 (in-memory나 localStorage 아님) | 이전 ai-chat-app의 placeholder 방식은 채택 안 함 |
| 백엔드 스택 | Node.js + Express + Mongoose | MongoDB 궁합, REST API |
| 배포 | 프론트 Vercel / 백엔드 Railway / DB MongoDB Atlas | 과제 요구사항 그대로 |

## 논의 중이었던 것: 구현 순서 (사용자 승인 대기)

3가지 접근 제시함:
- **A. 백엔드 먼저 전부 구축** — API 설계 안정적이지만 중간 결과물이 안 보임
- **B. 프론트엔드 먼저 목데이터로** — 눈에 빨리 보이지만 나중에 이중 작업 발생
- **C. 기능 단위 수직 슬라이스 (추천, 아직 사용자 승인 안 됨)** — 기능 하나(프론트+백엔드+DB 전부)를 완전히 동작하게 만들고 다음 기능으로 이동:
  1. 회원가입/로그인 (역할 선택, JWT 인증) — 풀스택으로 완성 (Railway/MongoDB Atlas 셋업 포함)
  2. 상담사 리스트/프로필 조회
  3. 매칭 신청 → 상담사 수락/거절(사유 포함)

## 다음 세션에서 할 일

1. 사용자에게 접근 방식(A/B/C) 최종 확인받기 — C 추천안 승인 여부
2. 승인되면 디자인을 섹션별로 제시 (아키텍처, 컴포넌트, 데이터 모델, 에러 처리, 테스트 전략) 하고 각 섹션 승인받기
3. 회원가입/로그인 데이터 모델 세부사항 확정 (상담사 프로필 필드: 전공/학년/상담분야/자기소개 등, 내담자 필드: 연령대/고민 카테고리 등) — 아직 논의 안 됨
4. 최종 스펙 문서로 이 파일을 갱신 (또는 별도 확정본 작성) 후 git 커밋
5. `writing-plans` 스킬로 전환해 실행 계획 작성
