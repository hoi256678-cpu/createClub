# 앱 셸 & 내비게이션 UI (승인됨)

> 상태: **승인 완료**. `writing-plans` 스킬로 넘어가 구현 계획 작성 예정.

## 배경

Slice 1(회원가입/로그인)까지 완료되어 실제 인증 기능이 프로덕션에 배포되어 있다(`2026-08-01-auth-slice-design.md`). 하지만 지금까지 앱의 나머지 화면은 만들어진 적이 없다.

사용자가 미리 만들어둔 두 개의 정적 HTML 목업이 있다:
- `create-club참고자료/somit_web_welcome_1.html` — 데스크탑용, 사이드바 내비게이션 + 페이지 전환 방식
- `create-club참고자료/somit_v8_welcome.html` — 모바일 앱용, 하단 탭바 + 화면(screen) 전환 방식

두 목업 모두 SUIT 폰트, 파스텔 블루 팔레트(`#9EB9E6` 계열)를 쓰며 홈/커뮤니티/채팅/심리검사/마이페이지/알림/로그인/게시글상세/글쓰기/설정 화면을 전부 포함한 풀 프로토타입이다. 이 문서는 이 두 목업을 참고해 실제 Next.js 앱에 **내비게이션 가능한 앱 셸과 화면 뼈대**를 만드는 작업을 다룬다.

## 이번 작업에서 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 두 목업의 관계 | 하나의 반응형 UI로 통합. 넓은 화면(데스크탑)에서는 사이드바+상단바, 좁은 화면(모바일)에서는 하단 탭바로 CSS 미디어쿼리 기준 자동 전환 |
| 이번 작업 범위 | 내비게이션 + 레이아웃 전체를 먼저 완성. 인증(회원가입/로그인)을 제외한 화면의 실제 기능(데이터 연동)은 이번엔 제외, 더미 데이터로 화면만 완성 |
| 라우팅 구조 | 목업처럼 하나의 페이지 안에서 JS로 전환하는 대신, 화면마다 실제 Next.js App Router URL로 분리 |
| 스타일링 방식 | 목업의 CSS를 그대로 쓰지 않고, 색상/폰트/간격 토큰을 Tailwind v4 토큰으로 이식한 뒤 유틸리티 클래스로 컴포넌트를 재작성 |
| 로그인/회원가입 재디자인 | 이번에 같이 새 디자인 적용(기존 JWT/bcrypt 기능은 그대로 유지) |
| 검증 방식 | 자동 테스트 없이 브라우저 수동 검증(데스크탑/모바일 뷰포트). 기존 auth 테스트(18/18)는 회귀 확인용으로 재실행만 |

## 아키텍처

```
app/
  (shell)/                 # 로그인 이후 화면들을 감싸는 라우트 그룹
    layout.tsx              # AppShell 렌더 (사이드바/상단바 or 하단탭)
    page.tsx                 # 홈 (기존 app/page.tsx를 이 그룹으로 이동)
    community/
      page.tsx
      [id]/page.tsx
      write/page.tsx
    chat/
      page.tsx
      [id]/page.tsx
    test/page.tsx
    mypage/page.tsx
    notifications/page.tsx
    settings/page.tsx
  login/page.tsx            # 재디자인, 기능 유지
  signup/page.tsx            # 재디자인, 기능 유지
  components/
    shell/
      AppShell.tsx           # 반응형 레이아웃 (사이드바+상단바 / 하단탭)
      Sidebar.tsx
      TopBar.tsx
      BottomNav.tsx
    ui/
      Card.tsx
      SectionTitle.tsx
      Chip.tsx
      Toast.tsx
    AuthStatus.tsx            # 기존 유지, AppShell 상단바에 통합
```

- 색상/폰트/라운드/그림자 등 디자인 토큰은 `app/globals.css`의 `@theme inline`에 이식한다. 기존 다크/오렌지 톤(`--ink`, `--accent` 등, 배포 스켈레톤 랜딩용으로 만들었던 값)은 새 파스텔 블루 팔레트로 교체한다.
- SUIT 폰트는 Google Fonts에 없으므로 `next/font/local`로 자체 호스팅한다(목업이 쓰는 jsdelivr CDN의 woff2 파일을 `public/fonts/`에 내려받아 사용).
- 다크모드(목업의 `.dark` 클래스)는 이번 스코프에서 제외하고 라이트 모드만 구현한다.
- 반응형 전환 브레이크포인트는 데스크탑 목업의 미디어쿼리 기준(`900px`)을 그대로 따른다: `900px` 이상은 사이드바+상단바, 미만은 하단 탭바.
- 상담사 프로필(`/counselors/[id]`)은 Slice 2에서 실제 데이터와 함께 만들 예정이라 이번 스코프에서 제외한다.

## 페이지 구성

| 라우트 | 화면 | 데이터 |
|---|---|---|
| `/` | 홈 (배너, 심리검사 카드, 명언, 인기글, 상담기관 배너) | 더미 |
| `/community` | 커뮤니티 목록(탭, 검색/필터, 글 목록) | 더미 |
| `/community/[id]` | 게시글 상세(투표, 댓글) | 더미 |
| `/community/write` | 글쓰기 폼 | 로컬 state만, 저장 미연결 |
| `/chat` | 채팅 목록 | 더미 |
| `/chat/[id]` | 채팅방 | 더미 메시지, 입력창 UI만 |
| `/test` | 심리검사 목록 + 응시 | 더미 문항, 결과 계산 로직은 목업 그대로 이식 |
| `/mypage` | 마이페이지(프로필 카드, 설정 진입점) | 더미 |
| `/notifications` | 알림 목록 | 더미 |
| `/settings` | 설정(목업의 통합 설정 화면) | 더미 |
| `/login`, `/signup` | 재디자인 | 실제 기능 유지 |

로그인이 필요한 화면(`/chat`, `/mypage`, `/notifications`)은 목업의 `authGuardWeb`과 동일한 역할을 프론트에서 수행한다: `GET /api/auth/me` 결과가 비로그인이면 `/login`으로 리다이렉트한다.

## 컴포넌트

- **`AppShell`**: 자식으로 페이지 콘텐츠를 받아 데스크탑에서는 좌측 고정 사이드바 + 상단바, 모바일(브레이크포인트 이하)에서는 하단 고정 탭바로 렌더링을 전환하는 반응형 레이아웃. 상단바에는 기존 `AuthStatus`를 통합한다.
- **`Sidebar` / `BottomNav`**: 홈/커뮤니티/채팅/심리검사/알림/마이페이지로 이동하는 내비게이션 항목. 현재 라우트에 따라 active 스타일 적용.
- **공통 UI 조각(`Card`, `SectionTitle`, `Chip`, `Toast`)**: 목업에서 반복되는 패턴을 재사용 가능한 컴포넌트로 분리.
- **더미 데이터**: 각 페이지 폴더 옆에 `mock.ts`를 두고 하드코딩된 배열(게시글, 채팅, 알림 등)을 컴포넌트가 렌더링한다. 나중에 실제 API로 교체하기 쉽도록 데이터 타입(shape)을 미리 정의해둔다.

## 데이터 흐름

1. 로그인하지 않은 사용자가 `/`에 접속하면 홈 화면은 보이되(공개 콘텐츠), `AppShell`의 로그인 필요 항목(채팅/마이페이지/알림)은 클릭 시 `/login`으로 보낸다.
2. 로그인한 사용자는 `AuthStatus`가 이미 하듯 `GET /api/auth/me`로 상태를 확인하고, 상단바/사이드바에 이름을 표시한다.
3. 각 페이지는 `mock.ts`의 더미 데이터를 그대로 렌더링한다. 실제 백엔드 연동은 이후 슬라이스(Slice 2 이후)에서 이 mock 데이터를 API 호출로 교체하는 방식으로 진행한다.

## 에러 처리

- `GET /api/auth/me` 실패/네트워크 오류 시 `AuthStatus`와 동일하게 조용히 비로그인 상태로 처리한다.
- 로그인 필요 페이지에 비로그인 상태로 직접 진입 시 `/login`으로 리다이렉트한다.
- 더미 데이터 기반 화면이라 그 외 에러 케이스(로딩 실패, 빈 상태 등)는 목업에 있는 빈 상태 디자인이 있으면 그대로 옮기고, 없으면 이번 스코프에서 다루지 않는다.

## 테스트 전략

자동 테스트를 추가하지 않는다. 순수 UI/네비게이션 작업이라 로직이 거의 없고, `npm run dev`로 각 라우트를 데스크탑/모바일 뷰포트에서 직접 열어 확인하는 브라우저 수동 검증으로 충분하다고 판단했다. 기존 백엔드 auth 테스트(18/18)는 이번 작업으로 회귀가 없는지 확인하는 용도로 재실행만 한다.

## 범위 밖 (Out of scope)

- 커뮤니티/채팅/심리검사/마이페이지/알림/설정의 실제 데이터 연동(백엔드 API, DB 스키마) — 이후 슬라이스
- 상담사 리스트/프로필 조회(Slice 2)
- 다크 모드
- 카카오 로그인 등 소셜 로그인(목업엔 있으나 기존 auth-slice 스코프 밖)
- PWA/네이티브 앱 전환
